# UI doğrulama — 2026-08-19

Gerçek headless Chrome ile `1920×1080` ve `1100×900` viewport'larında admin ve eczacı rolleri test edildi. Karşılaştırma için kullanıcı yönetimi, algoritma/medikal yönetim ve görüş-destek ekranları olgun referans olarak kullanıldı.

## Doğrulanan akışlar

- Admin dashboard: legacy “Kiosk Etkileşimleri” yok; aylık/haftalık etkileşim ve satıştan oluşan dört ortak grafik var.
- Son dashboard revizyonunda 1920px görünümde üç kolon aynı satırda ölçüldü (`722px / 438px / 385px`): aylıklar tek panel, haftalıklar tek kompakt panel, kategori ve satış yapan eczane donut'ları üçüncü kolon. 1100px responsive turda yatay overflow oluşmadı.
- Grafik gün tıklaması gerçek tarayıcıda doğrulandı: etkileşim `/admin/kiosk-activities?tab=sessions&start_date=...&end_date=...`, satış `/admin/kiosk-activities?tab=sales&start_date=...&end_date=...` açtı.
- Admin duyuru liste ve düzenleme modalı: backend `system_key` değerleri görünmüyor; “Sistem Duyurusu” etiketi kullanılıyor.
- Cihaz yönetimi: karttaki “Eczaneye Taşı” aksiyonu tam başlıklı standart modalı açıyor; mevcut eczane, hedef arama ve neden alanları görünüyor.
- Eczacı dashboard: hedef eczaneye bağlı geçici genel QA duyurusu layout mount'unda otomatik açıldı. “Okudum” isteği `201` döndü; hard reload sonrasında modal sayısı `0` kaldı. Geçici duyuru doğrulama sonrasında silindi.
- İncelenen sayfalarda yatay overflow veya browser console error görülmedi.
- Ağ turundaki uygulama API response'ları başarılıydı. Yalnız mevcut `/favicon.ico` `404` ve route değişiminden kaynaklanan beklenen `net::ERR_ABORTED` kaydı görüldü.
